## 1. 实验设计：专门针对四大维度的三套专用数据集

为彻底检验 **Context 定义、行为控制面、五维效果与真实缓存经济学成本**，并直面阶段 6 遗留的两大公开瓶颈（① 小窗口下 `cpat` v1 往返税导致比 `threshold` 更贵；② 静态文件可重读掩盖了不可重读场景的恢复缺陷），构建三套 100% 确定性精确判分的专用评测集：

1. **`bounded-research`（32K 硬窗口，14 篇档案 ~69.7K tokens = 2.2× 窗口，禁用 `grep`）**：
   - 5 连问：全局最高准确率聚合、两跳依赖链追踪、早期档案尾部深埋 `INC-...` + `SHA-...` 回访、全局最低准确率聚合、中段档案深埋代码回访。
2. **`ephemeral-stream`（22K 硬窗口，10 批一次性不可重读遥测流 ~43.6K tokens = 2.0× 窗口，无文件工具）**：
   - 状态化单向游标 `pull_telemetry_batch`：一旦消费永不可重拉；每批在 7,000+ 字符深处埋入 16 条细粒度分布式追踪记录（共 **160 条 `TRC-...` span**，远超任何单段摘要的预记忆容量）。4 连问检验全局峰值聚合 + 早期批次任意 `TRC-...` 的字面精确召回（复现 `MemoryAgentBench` 单句精确召回挑战）。
3. **`pollution-spec`（22K 硬窗口，诱饵日志污染 + 中途权威需求覆写 ~29.1K tokens）**：
   - 第 1 问诱导读取 `staging` 环境的 `RedisShardPool` / `SLA=500ms`（`required_slots=6000`）巨量日志；第 2 问用户发出紧急覆写指令：废除一切 staging/Redis/500ms 假设，切至生产 `LocalRingBuffer` 并将权威 `active_sla_ms` 更新为 `150ms`（正确 `required_slots=1800`，缺陷码 `BUG-RB-404`）；第 3 问检验无污染一致性。

## 4. 关键机制发现与根因证据

1. **为什么 `ephemeral-stream` 上 `threshold` 和 `cpat` v1 双双跌至 25%（回访 0%），唯独 `harness` 100%？**
   - **`threshold` 的死穴**：自动 offload 只留前 300 字符，且没有恢复工具；面对一次性游标流，模型在日志中坦白：*“The offload note points to `artifact://tool_219@v1`, but I have no `artifact_get` tool... and the cursor is one-shot, so the specific values are unrecoverable.”*
   - **`cpat` v1（写时主观丢弃）的死穴**：完全印证了 **Scroll（arXiv:2608.21690）** 指出的写时压缩悖论！`cpat` v1 在回答第 1 问（只看批次错误率峰值）时，认为 16 行 `SPAN_RECORD` 表是无关噪声，主动执行了摘要 + `set_visibility=hidden` 处置陈旧块；等到第 2–4 问追问 `TRC-0214` 时，模型回复：*“I can't answer that one — the data is gone... The 16-row SPAN_RECORD table was disposed as noise at the time it was read.”*
   - **`harness` v2 的解法**：写入时 100% 原文进入零依赖 `SearchIndex`（行级 + 正则 + 窗口 BM25），视图层仅做非破坏性分辨率降级（`full -> digest`）；追问到达时，主模型单次调用 `context_query(query="TRC-0214")` 即精确命中 `[#tool_276:L153]`，墙钟耗时仅 **40.9s**（比 `cpat` v1 的 129.9s 快 **3.2 倍**）。

2. **为什么 `harness` 彻底攻克了 CPAT v1 的“小窗口成本倒挂”问题？**
   - 消除了每轮末尾重排的 `<context_manifest>` 伪用户消息（常规步实现 **100% 字节级前缀延续**，`bounded-research` 缓存命中率从 `cpat` v1 的 `57.7%` 跃升至 **`81.6%`**，部分回合达 `98%`）。
   - 将摘要生成与压缩判断移交给异步 `deepseek-flash`（`reasoning_effort="low"`），主模型无需再跑任何 `context_update` 额外回合。在 `Pro + Flash` 异构配置下，即使在 15K 极小窗口，`harness` 总账单（`$0.0195`）也首次**正面击败了零治理开销的被动 `threshold`（`$0.0287`，省 32.1%）**，更比 `cpat` v1（`$0.1332`）省下 **85.4%**。

3. **为什么 `pollution-spec` 上 `threshold` 算错简单算术（33.3%），而 `harness` 8 轮全对（100%）？**
   - `threshold` 窗口中残留大量未清洗的 staging 噪声（`retry_backoff=120ms`、`500ms`、`13,292` peak tokens），在上下文效用稀释与干扰下把 `(4000 × 150 / 1000) × 3 = 1800` 幻觉算成 `400 × 3 = 1200`；
   - `harness` 在用户发出覆写指令时触发 `AC3` 隔离审计与问题边界降级，峰值水位压在 `8,669`（均值仅 `3,606`），缓存命中率 `67.5%`，8 轮全部一次答对。
